C / C++ 공부 환경 안내 (gvim + Visual Studio 2022, Windows 11)
=============================================================

gvim으로 C, C++ 코드를 작성하고 Visual Studio 2022 컴파일러로 빌드해서 실행,
디버깅하는 환경이다. 이 폴더 하나에 설정이 모두 들어 있어서, 프로그램 두 개를
설치하고 이 폴더를 복사하면 어느 Windows PC에서나 같은 환경이 된다. 자세한 구축
과정과 설정 파일 전문은 C_C++_개발환경_구축가이드.docx에 있다.


1. 구성

파일
gvim.bat               이 폴더를 gvim으로 연다
gvim_c_study.vim       gvim 설정. gvim_handmade.vim을 불러온 뒤 빌드와 실행 대상을 정한다
gvim_handmade.vim      편집 설정, 단축키, 글꼴, 색 테마 (Handmade Hero 공부 환경과 같은 파일)
emacs.bat              이 폴더를 Emacs로 연다 (Emacs를 쓸 때. Emacs_C_C++_가이드.md)
emacs_c_study.el       Emacs 설정. handmade.emacs를 불러온 뒤 빌드와 실행 대상을 정한다
handmade.emacs         Emacs 편집 설정 (Handmade Hero 날짜 폴더의 .emacs와 같은 파일)
emacs_theme.el         Emacs 글꼴과 색 (gvim과 같게, Ctrl+마우스 휠로 크기)
emacs_edit.el          Emacs C/C++ 편집 기능 (gvim과 같게: 괄호 자동 완성, Tab 빠져나가기 등)
build.bat             .c 또는 .cpp 파일 하나를 빌드한다
run.bat                프로그램을 실행하고, 끝나면 종료 코드를 보여 준 뒤 키 입력을 기다린다
shell.bat              Visual Studio 2022 x64 컴파일러 환경 준비
c\, cpp\               C 예제, C++ 예제
<소스 폴더>\build\      빌드 결과(이름.exe, .obj, .pdb). 지워도 다시 빌드하면 생긴다
C_C++_빌드가이드.txt     이 문서
C_C++_개발환경_구축가이드.docx   다른 PC 구축 가이드 (Word)
Emacs_C_C++_가이드.md  Emacs로 쓰는 방법

예제
c\01_hello.c           printf 출력, 자료형 크기, 반복문, 함수
c\02_input.c           scanf로 이름(한글)과 정수 입력, 합계와 평균
c\03_struct_file.c     구조체 배열, 포인터, qsort, malloc, 파일 쓰기와 읽기
cpp\01_hello.cpp       iostream, string, vector, 범위 for, 람다, sort, std::format
cpp\02_class.cpp       클래스, 생성자와 소멸자, 연산자 오버로딩, 템플릿, unique_ptr

필요한 프로그램
- Visual Studio 2022   "C++를 사용한 데스크톱 개발" 워크로드. C:\Program Files\Microsoft
                       Visual Studio\2022 아래의 Community, Professional, Enterprise,
                       BuildTools 순서로 찾는다
- Vim 9 (gvim) 64비트  C:\Program Files\Vim\vim9x\gvim.exe. 가장 높은 버전을 쓴다
- 글꼴 (선택)          JetBrainsMono Nerd Font Mono. 없으면 Consolas로 표시된다
- GNU Emacs (선택)     Emacs로 쓸 때. C:\Program Files\Emacs\emacs-* 아래에서 찾는다

폴더는 어디에 두어도 된다(예: D:\Work\01.c_study). 경로에 공백이 있어도 되지만,
한글이 들어간 경로는 시험하지 않았으므로 영문 경로를 권장한다.


2. 다른 PC에 설치하기

① Visual Studio 2022를 설치한다. 설치 프로그램의 워크로드 탭에서 "C++를 사용한
   데스크톱 개발"을 고른다(MSVC v143 빌드 도구와 Windows 11 SDK 포함).
② www.vim.org의 Download 안내에 따라 Windows용 64비트 설치 파일(gvim_9.x_x64.exe)을
   받아 기본 위치(C:\Program Files\Vim)에 설치한다.
③ (선택) www.nerdfonts.com의 Downloads에서 JetBrainsMono를 받아 압축을 풀고
   JetBrainsMonoNerdFontMono-Regular.ttf를 마우스 오른쪽 단추로 눌러 "설치"한다.
④ 이 폴더를 새 PC로 복사한다. 압축 파일로 받았다면 PowerShell에서 푼다.

   Expand-Archive -Path "$env:USERPROFILE\Downloads\01.c_study_환경설정.zip" -DestinationPath 'D:\Work'
   Get-ChildItem -Recurse 'D:\Work\01.c_study' | Unblock-File

   (Unblock-File은 인터넷이나 메일로 받은 파일의 차단 표시를 지운다. USB로 옮겼다면
   없어도 된다.)
⑤ 확인한다. 한글이 바르게 나오고 마지막에 exited with code 0이 보이면 된다.

   Set-Location 'D:\Work\01.c_study'
   .\build.bat c\01_hello.c
   .\run.bat c\build\01_hello.exe
   .\gvim.bat c\01_hello.c

   gvim에서 Alt+m을 누르면 아래에 "-- Build succeeded."가, F5를 누르면 새 콘솔
   창에 실행 결과가 나온다.

설치 위치가 기본과 다르면 13절, 오류 메시지는 12절을 본다.


3. 실행 방법

PowerShell에서 이 폴더로 이동한 뒤 실행한다(예: Set-Location 'D:\Work\01.c_study').

.\gvim.bat                  폴더 목록으로 시작
.\gvim.bat c\01_hello.c     파일 열기
.\gvim.bat c\04_array.c     새 파일 만들기

PowerShell에서는 앞의 .\를 반드시 붙인다. 탐색기에서 gvim.bat를 더블클릭하면
폴더 목록으로 시작한다. 개인 Vim 설정(_vimrc)은 읽지 않으므로 그대로 남는다.

시작하면 창이 최대화되고 좌우 2분할로 열린다. 작업 폴더는 항상 이 폴더이다.
상태 줄 오른쪽의 [01_hello.c]는 현재 프로그램(6절), 그 옆은 빌드 상태이다.

폴더 목록에서 쓰는 키
- Enter    파일 열기, 폴더 들어가기
- -        상위 폴더로
- %        새 파일 이름을 입력해서 만들기
- Alt+f    파일 이름을 직접 입력해서 열기(Tab으로 이름 완성). 예: Alt+f c\05_loop.c


4. 기본 작업 순서

① 새 파일을 만든다. Alt+f를 누르고 c\04_array.c 를 입력한 뒤 Enter.
   새 .c, .cpp 파일에는 main 함수 틀이 들어가고, main 안에서 입력 모드로 시작한다.

   #include <stdio.h>

   int
   main(void)
   {
       |
       return(0);
   }

   함수 이름을 줄 맨 앞에 두는 이 형식을 따르면 Alt+j의 함수 목록에 나온다.
② 코드를 작성한다. jj로 일반 모드로 돌아간다.
③ Alt+m: 저장하고 빌드한다. 아래 창에 결과가 나온다.
   오류가 있으면 F9로 첫 오류 위치로 가고, Alt+n(다음), Alt+Shift+n(이전)으로 이동한다.
④ F5: 새 콘솔 창에서 실행한다. 프로그램이 끝나면 다음과 같이 표시되고, 아무 키나
   누르면 창이 닫힌다.

   ---- 01_hello.exe exited with code 0 ----
   계속하려면 아무 키나 누르십시오 . . .

   Ctrl+F5는 빌드한 뒤 성공하면 바로 실행한다.
⑤ 입력을 기다리는 프로그램(scanf, std::cin)은 그 콘솔 창에서 입력한다. 한글도 된다.
⑥ 끝나지 않는 프로그램은 gvim에서 Shift+F5로 멈춘다. 실행 창에 종료 코드가 표시되고,
   아무 키나 누르면 창이 닫힌다.


5. 단축키

Vim에는 입력 모드와 일반 모드가 있다. i나 a로 입력을 시작하고 Esc 또는 jj로 일반
모드로 돌아간다. 아래 키는 대부분 두 모드에서 모두 동작한다.

빌드와 실행
  Alt+m                 현재 프로그램을 저장하고 빌드
  Ctrl+F5               빌드한 뒤 성공하면 실행
  F5                    실행 (새 콘솔 창, 소스 파일이 있는 폴더에서)
  Shift+F5              실행 중인 현재 프로그램 강제 종료
  F6                    Visual Studio 디버거로 열기 (10절)
  F9                    첫 번째 오류 위치로
  Alt+n, F11            다음 오류
  Alt+Shift+n, F10      이전 오류

파일과 창
  Alt+f / Alt+Shift+f   파일 열기 / 오른쪽에 분할해서 열기
  Alt+s                 저장
  Alt+b / Alt+Shift+b   열린 파일(버퍼) 전환 / 분할해서 전환
  Alt+k                 현재 파일 닫기. 빌드 창이나 목록 창에서는 그 창을 닫는다
  Alt+r                 파일을 디스크 내용으로 다시 읽기
  Alt+w                 분할 창 사이 이동
  Alt+p                 창 최대화
  Ctrl+x, Ctrl+c        gvim 종료 (저장하지 않은 파일이 있으면 묻는다)
  Ctrl+마우스 휠 위/아래  글꼴 크기를 1씩 키우기/줄이기(6 ~ 40). 창 크기는 그대로이고
                        보이는 줄과 칸 수가 바뀐다. gvim을 닫으면 원래 크기(12)

찾기와 이동
  Ctrl+s                앞으로 검색. Enter로 끝낸다
  Alt+g                 줄 번호로 이동
  Alt+j                 현재 파일의 함수 목록. 항목에서 Enter로 이동
  F4                    커서 아래 단어를 이 폴더 전체(.c .cpp .h)에서 찾기
  Alt+위/아래            이전/다음 빈 줄로
  F12, Alt+c            .c/.cpp 와 .h 전환. Alt+Shift+c는 오른쪽에 분할해서 연다
  %                     짝이 되는 괄호로
  Alt+x                 명령 입력(:)
  Ctrl+g                입력 중인 명령이나 선택 취소

편집
  Alt+u                 실행 취소
  Alt+Space             선택 시작
  Alt+q / Alt+z / Alt+a 선택 영역 복사 / 잘라내기 / 붙여넣기
  Alt+o                 커서 이후 또는 선택 영역에서 확인하며 바꾸기
  Alt+d                 현재 줄 또는 선택 영역을 아래에 복제
  Alt+Shift+위/아래      현재 줄 또는 선택 영역을 위/아래로 이동
  Alt+Enter             아래에 새 줄을 열고 입력
  Alt+;                 현재 줄 또는 선택 영역을 // 주석으로 바꾸거나 해제
  Shift+Tab / Ctrl+Tab  현재 줄 / 선택 영역 들여쓰기
  za / zM / zR          커서 위치 접기·펼치기 / 모두 접기 / 모두 펼치기

입력 편의 (입력 모드, C/C++ 파일)
- ( [ { " ' 를 입력하면 닫는 문자가 함께 들어가고 커서는 그 사이에 놓인다. 닫는
  문자를 직접 입력하면 새로 넣지 않고 지나간다. 빈 짝 사이의 Backspace는 둘 다
  지운다. { 와 } 사이에서 Enter를 누르면 세 줄로 나뉜다.
- Tab: 커서 뒤가 ) ] } 나 닫는 따옴표이면 그 뒤로 빠져나가고, 커서 앞이 단어이면
  앞에서 쓴 단어로 자동 완성하고, 그 외에는 공백 4칸을 넣는다. 괄호 안에서 자동
  완성은 Alt+/, 후보 이동은 Ctrl+p / Ctrl+n, 확정은 Enter.
- jj: j를 0.5초 안에 두 번 누르면 일반 모드로 돌아간다(한글 입력 상태에서는 안 된다).
- 코드 조각: 아래 단어를 입력하고 Alt+e를 누르면 코드가 들어간다.
  if, else, for, while, switch, case, struct, inc(#include <>)
- 새 .h 파일에는 #if !defined(이름_H) 형식의 include guard가 들어간다.

명령줄에서 쓸 때 (이 폴더에서)
.\build.bat c\01_hello.c
.\run.bat c\build\01_hello.exe


6. 현재 프로그램

- Alt+m, F5, Ctrl+F5, Shift+F5, F6의 대상은 마지막으로 들어간 .c 또는 .cpp 파일이다.
  상태 줄의 [ ] 안에 표시된다.
- .h 파일, 빌드 결과 창, 폴더 목록으로 옮겨도 바뀌지 않는다. 헤더를 고치다가 Alt+m을
  누르면 직전에 보던 .c/.cpp 프로그램이 빌드된다.
- .c 또는 .cpp 파일 하나가 프로그램 하나이다. 코드를 여러 파일로 나누려면 프로그램
  파일에서 #include "stack.c" 로 포함한다(unity build). 포함되는 파일을 열어 둔 채
  Alt+m을 누르면 그 파일만 빌드되어 main이 없다는 링크 오류(LNK2019, LNK1120)가
  난다. 프로그램 파일로 옮겨서 빌드한다.
- 결과는 소스 폴더의 build\이름.exe이다. 같은 폴더에 a.c와 a.cpp처럼 확장자만 다른
  파일을 두면 같은 a.exe를 덮어쓰므로 이름을 다르게 짓는다.


7. 빌드 옵션 (build.bat)

cl -nologo -FC -Z7 -Od -MTd -RTC1 -W4 -source-charset:utf-8 -D_CRT_SECURE_NO_WARNINGS
   .c 파일    -std:c17
   .cpp 파일  -std:c++20 -EHsc -Zc:__cplusplus
link -incremental:no user32.lib gdi32.lib

  옵션                         의미
  -FC                          오류 메시지에 전체 경로 (F9 이동에 필요)
  -Z7                          디버깅 정보. 빌드하면 이름.pdb가 생긴다
  -Od                          최적화 끔 (디버깅할 때 변수와 줄이 소스와 맞는다)
  -MTd                         디버그용 C 런타임
  -RTC1                        초기화하지 않은 변수 사용, 스택 손상을 실행 중에 검사
  -W4                          경고 수준 4. 경고는 표시되지만 빌드를 멈추지 않는다
  -source-charset:utf-8        소스를 UTF-8로 읽는다 (8절)
  -D_CRT_SECURE_NO_WARNINGS    scanf, strcpy 등을 쓸 때 나오는 C4996 경고를 끈다
  -std:c17, -std:c++20         C17, C++20 표준
  -EHsc                        C++ 예외 처리 (iostream 등에 필요)
  -Zc:__cplusplus              __cplusplus 값을 실제 표준(202002)으로 표시
  user32.lib gdi32.lib         MessageBox 등 Windows API를 시험할 때 필요

-WX가 없어서 경고가 있어도 빌드된다. 경고도 빌드 결과 창에 나오고 F9로 이동할 수
있으므로 읽고 고치는 습관을 들인다. 옵션을 바꾸려면 build.bat의 CommonCompilerFlags와
LanguageFlags 줄을 고친다.


8. 한글 처리

- gvim은 파일을 UTF-8(BOM 없음)로 저장한다. build.bat가 -source-charset:utf-8로
  소스를 UTF-8로 읽는다.
- 문자열 상수는 Windows 코드 페이지(한국어 Windows는 949)로 바뀐다. 그래서 콘솔에
  한글이 그대로 보이고, scanf 등으로 한글을 입력받을 수 있다.
  sizeof("한글")은 5이다(한글 한 글자 2바이트, 끝의 0 1바이트).
- /utf-8 옵션을 쓰면 문자열이 UTF-8(한 글자 3바이트)이 되어, 콘솔을 chcp 65001로
  바꾸지 않으면 한글이 깨진다. 그래서 이 환경에서는 쓰지 않는다.
- 다른 곳에서 가져온 CP949(EUC-KR) 소스는 gvim이 CP949로 열고 CP949로 저장한다.
  그대로 빌드하면 한글이 있는 곳마다 C4828 경고가 나고, C2001(상수에 줄 바꿈 문자가
  있습니다) 같은 오류로 실패하기도 한다. :set fileencoding? 로 확인하고,
  :set fileencoding=utf-8 을 입력한 뒤 저장하면 UTF-8로 바뀐다.
- 한국어가 아닌 Windows나 "Unicode UTF-8 사용(Beta)"을 켠 Windows는 시험하지 않았다.


9. 실행 폴더와 파일 경로

- F5는 소스 파일이 있는 폴더에서 실행한다. fopen("scores.txt", "w")처럼 상대 경로로
  쓴 파일은 그 폴더에 생긴다. c\03_struct_file.c를 실행하면 c\scores.txt가 생긴다.
- 프로그램에 읽을 파일이 필요하면 소스 파일과 같은 폴더에 둔다.
- 명령줄에서 run.bat를 쓰면 현재 폴더에서 실행된다.
- 실행 창은 gvim을 닫아도 남아 있다. 아무 키나 누르면 닫힌다.


10. 디버깅 (F6)

F6을 누르면 Visual Studio가 현재 프로그램을 디버거로 연다(devenv /DebugExe).
- 소스 파일을 열고(파일 > 열기 > 파일, Ctrl+O) 중단점을 건 뒤(F9) 디버그 > 디버깅
  시작(F5)으로 실행한다. F10은 한 줄 실행, F11은 함수 안으로, Shift+F5는 중지이다.
- -Z7 -Od로 빌드했으므로 지역 변수, 호출 스택을 볼 수 있다.
- 소스를 고쳤으면 디버깅을 멈추고 gvim에서 Alt+m으로 빌드한 뒤 다시 시작한다.
  Visual Studio는 빌드를 하지 않는다. 디버깅 중에는 exe가 잠겨서 빌드가
  "is running" 메시지로 멈춘다.
- 디버거의 작업 폴더는 소스 폴더가 아닐 수 있다. 상대 경로로 파일을 여는 프로그램은
  프로젝트 속성 > 디버깅 > 작업 디렉터리를 소스 폴더로 지정한다.


11. 글꼴과 색

글꼴과 색은 gvim_handmade.vim의 Font and colors 부분에서 정한다.
- 글꼴: JetBrainsMono Nerd Font Mono 12. Windows에는 JetBrainsMono NFM이라는 이름으로
  등록되므로 설정도 이 이름을 쓴다. 없는 PC에서는 Consolas 12로 표시된다.
- 한글: 글꼴을 따로 정하지 않아 Windows가 고르는 대체 글꼴(맑은 고딕)로 표시된다.
  gvim은 한글 글꼴로 고정폭 글꼴만 받으므로 맑은 고딕을 직접 지정할 수는 없다.
- 색: 어두운 테마. Vim의 기본 C/C++ 문법은 이름에 색을 넣지 않으므로 이름과 함수
  이름 규칙을 더했다.

  배경 / 현재 줄                     #1E1E1E / #282828
  이름(변수, 형식, 객체)              #BDB76B 카키      Screen, uip, m_Panels
  함수 이름(정의, 일반 호출)           #FF8000 주황      initialise, move, main
  . 이나 -> 뒤의 멤버 함수, 기호       #DADADA 흰색      push_back, begin, ( ) ;
  형식 키워드                        #569CD6 파랑      void, auto, int, static
  제어 키워드                        #D8A0DF 분홍      while, for, if, return, this
  주석 / 문자열 / 전처리기             #57A64A / #D69D85 / #9B9B9B
  줄 번호 / 현재 줄 번호              #858585 / #D9D9D9
  짝 괄호                           #FFD700 금색 (배경 #3A3A3A)

- 주석 안의 TODO는 빨간색, NOTE는 초록색, STUDY와 IMPORTANT는 노란색으로 강조된다.


12. 자주 발생하는 문제

- "xxx.exe is running. Close it (Shift+F5 in gvim) and build again."
  그 프로그램의 실행 창이 아직 열려 있거나 디버깅 중이다. 실행 창에서 아무 키나
  누르거나 Shift+F5로 끝낸 뒤 다시 빌드한다.
- "Nothing to run. Build xxx first (Alt+m)."
  아직 빌드하지 않았다. Alt+m 또는 Ctrl+F5.
- "Open a .c or .cpp file first." / 빌드 창에 "Usage: build.bat file.c ..."
  현재 프로그램이 없다. .c 또는 .cpp 파일을 연다.
- 실행 창에 "older than the source"가 표시됨
  소스를 고친 뒤 빌드하지 않고 F5를 눌렀다. 실행은 이전 프로그램으로 된다.
  Ctrl+F5를 쓰면 항상 빌드한 뒤 실행한다.
- LNK2019 main, LNK1120
  main이 없는 파일(포함용 .c 등)을 빌드했다. 6절 참고.
- 한글이 깨지거나 C4828 경고가 많이 나옴
  소스가 CP949로 저장되어 있다. 8절 참고.
- Visual Studio 2022 C++ tools were not found / vcvarsall.bat was not found at ...
  Visual Studio 2022나 C++ 워크로드가 없거나, shell.bat에 적은 경로가 틀렸다.
  Visual Studio Installer에서 "C++를 사용한 데스크톱 개발"을 확인하거나 13절을 본다.
- gvim was not found in ... / gvim was not found at ...
  C:\Program Files\Vim\vim9x에 gvim이 없거나 gvim.bat에 적은 경로가 틀렸다.
  Vim 9를 설치하거나 13절을 본다.
- gvim_handmade.vim was not found 메시지
  이 폴더에 gvim_handmade.vim이 없다. 원래 폴더나 압축 파일에서 다시 복사한다.
- 글꼴이 JetBrains Mono가 아니라 Consolas로 보임
  JetBrainsMono Nerd Font Mono가 설치되어 있지 않다. 2절 ③대로 설치하고 gvim을
  다시 연다.
- Alt 키가 메뉴로 가거나 단축키가 동작하지 않음
  gvim.bat로 열지 않았다. 창 제목이 "gvim - 01.c_study"로 시작하는지 확인한다.
- jj나 일반 모드 명령이 동작하지 않음
  한글 입력 상태이다. 한/영 키로 영문 상태로 바꾼다.
- 스크립트를 실행할 수 없다는 보안 경고
  인터넷에서 받은 파일 표시가 남아 있다. 2절 ④의 Unblock-File을 실행한다.


13. 설정을 바꿀 때

- Visual Studio가 기본 폴더가 아닌 곳에 있으면 shell.bat의 set "vcvars=" 줄에
  vcvarsall.bat의 전체 경로를 넣는다.
    set "vcvars=D:\VS2022\VC\Auxiliary\Build\vcvarsall.bat"
- gvim이 기본 폴더가 아닌 곳에 있거나 Vim 8 이하이면 gvim.bat의 set "gvim_gui=" 줄에
  gvim.exe의 전체 경로를 넣는다.
    set "gvim_gui=D:\Tools\Vim\vim92\gvim.exe"
- 컴파일 옵션: build.bat의 CommonCompilerFlags, LanguageFlags
- 글꼴 크기: gvim_handmade.vim의 set guifont=JetBrainsMono_NFM:h12,Consolas:h12 줄에서
  h12 두 곳을 바꾼다(예: h14). 지금 창에서만 잠깐 바꿀 때는 Ctrl+마우스 휠을 쓴다.
- 색: gvim_handmade.vim의 highlight 줄
- 편집 기능, 단축키, 코드 조각: gvim_handmade.vim
- 새 파일 틀: gvim_c_study.vim의 s:NewProgram 함수
- 이 폴더에만 적용할 설정: gvim_c_study.vim 끝에 추가
설정을 바꾼 뒤에는 gvim을 다시 열어야 적용된다.
